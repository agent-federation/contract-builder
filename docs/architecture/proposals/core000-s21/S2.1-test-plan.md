# CORE-000 S2.1 test plan

**Status:** planning record. S2.1 implementation was authorized on 2026-11-04 and is not yet
performed. Test matrix for the S2.1 implementation proposed in
[`S2.1-implementation-plan.md`](S2.1-implementation-plan.md). Baseline:
`8d881d410c9945f7f5925fbf5772b06be2e9cc120` (existing `tests/core000.test.ts`: 16 pass;
`bun test`: 308 pass / 22 files).
**Boundary labels:** **S2.1** — added or updated by S2.1; **S2.3** — focused failing test for one of
the 11 new codes, stays out of S2.1; **S3** — N1–N18 matrix, stays out of S2.1 and S2.3.

All S2.1 tests assert behaviour through the public `runBuild` path or the profile declaration
itself. Synthetic objects used for schema/accessor unit checks are test inputs only; they are not
project data, evidence or verification records.

## 3. Run strategy

1. Implement on a branch off `main` after the S2.1 authorization; keep the change to the paths in
   [`S2.1-change-inventory.md`](S2.1-change-inventory.md).
2. Run, in order: `bun install --frozen-lockfile`, `bun run typecheck`, `bun test`,
   `bun test tests/core000.test.ts`, `bun run check`, `bun run build:release`.
3. Run the harness directly for S2.1-POS-01, S2.1-POS-02a/02b and S2.1-POS-03; confirm
   `git status --short` is empty after every run.
4. Re-run the two-process repeat on the final commit and record `inputDigest`, artifact SHA-256 and
   the diagnostic order in the PR body.
5. Report the CI run from the pinned Bun 1.4.2 environment; a local run on another Bun version is a
   recorded deviation, not CI evidence.

### 3.2 Test-input discipline

- No new fixture directory and no project copy is committed.
- Synthetic schema/accessor objects live in the test file and never enter `contracts/core000/` or
  `evidence/`.
- The existing mutation helper is unchanged in S2.1; S2.3 adds new named mutations with one field
  changed per case and an exact expected outcome.
- No test writes to the repository; the harness's `assertOutsideRepository` and workspace snapshot
  remain the enforcement.
