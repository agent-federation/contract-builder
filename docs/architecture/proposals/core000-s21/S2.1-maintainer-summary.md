## Recommendations

1. Q1 is decided and reflected: 9 phases, 8 `hasPrerequisite` edges, zero transition instances,
   29 relations. Accept the proposal's default answers for the remaining questions: omit
   `TB-CONSUMER-EXTENSION`, include the D14 consent interface/diagnostic rows, diagnostic `id` = code
   with an open `status` string, the raw-document accessor for the reserved `kind` fields, defensive
   implementations for the two schema-redundant checks, the deterministic part of the status/class
   rule, seven manifest-name dependency rows, no S2.1 evidence/draft commit, and all surfaces public
   (19 diagnostics).
2. Freeze the structure vocabulary before implementation; it is the main review surface and the only
   part that the S2 package cannot settle by itself.
3. Keep S2.1/S2.2/S2.3/S3 separate as the accepted package requires; S2.1 implements the surface and
   the checks, S2.3 proves the 11 new checks, S3 owns N1–N18.
